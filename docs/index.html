02 项目背景

真实对话不是一问一答，而是并行流动的。

现实中的人与人交流天然具备全双工特征。倾听、表达、打断、反馈、停顿和接话往往同时发生。 传统语音助手长期受限于半双工范式，用户必须先说完，系统才能回答；系统一旦开始长篇回答，用户也很难自然插话。 Lychee-FD 的目标，是让语音大模型具备更接近真人交流的交互节奏。

①

传统半双工

用户说完，系统才回答。用户必须等待系统完整说完。

②

级联系统

依赖语音识别、语言模型、语音合成、外部打断检测等多个模块，容易产生延迟和错误传播。

荔

Lychee-FD

原生端到端全双工建模，在统一框架内同时处理听、说、语义和控制。

优化前

等待、冗长、难以插话

用户只能等系统讲完，再重新表达需求。

优化后

插话、停止、立即调整

用户像真人沟通一样随时补充，系统实时理解并改口。

03 三大核心挑战

全双工语音交互的三个关键挑战

01

语义准确保持

用户长时间表达、补充条件、自我纠正时，系统仍要保持语义一致，不能越说越偏。

用户补充条件会议助理长段记录复杂任务实时改写
02

打断精确响应

用户真正改变需求时，系统要立即停止当前回答，并切换到新的语义指令。

中途改需求要求变短立即纠正
03

反馈及时触达

用户说“嗯”“对”“明白”时，系统不能误以为是打断；模型自己也应该能用短反馈降低等待焦虑。

用户附和模型附和情感陪伴会议记录

04 技术根因

根本瓶颈：模态冲突与语义稀释

这一部分是 Lychee-FD 的技术深度核心：问题不只是“能不能打断”，而是全双工训练时语音、语义与控制目标如何共存。

模态冲突深层目标开始分叉

在浅层，语音和语义目标还能共享一些通用表示；但到了深层，声学建模和语义建模的优化方向会出现冲突。

语义稀释文本监督被音频密度淹没

音频 token 很密，文本 token 很稀。时间对齐会引入大量 padding，导致语义监督变弱。

Lychee-FD 的设计不是简单堆模块，而是针对这两个根因进行结构性解决。

06 语义对齐通道

让模型说话时，脑中仍有清晰的语义轨迹

语义对齐通道可以理解为模型的“内部独白”。它在训练时提供连续、清晰的文本语义监督，让模型在生成语音的同时仍然保持逻辑连贯。

内部独白

语义锚点持续发光

在语音生成过程中，语义对齐通道为模型保留一条连续文本轨迹，让“说出来的声音”和“脑中的意思”保持同步。

语义流我明白你的意思我们重新安排……
声学流音频帧音频帧音频帧音频帧音频帧音频帧音频帧……
控制流开始继续监听停止更新恢复接话……
没有语义对齐

语义被 padding 稀释

文本监督断续变弱，模型更容易只跟随声学目标。

加入语义对齐

内部独白稳定牵引

语义流持续发光，回答更连贯，也更不容易越说越偏。

Lychee-FD 不是盲目发声，而是一边说话，一边保持清晰思考。
